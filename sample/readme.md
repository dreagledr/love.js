# fetch demo

A small LÖVE game that talks to an HTTP API, to show off the `http` module that
this fork adds on top of the Emscripten Fetch API (`emscripten_fetch`).

```
sample/
  game/            the game sources (this is the interesting part)
  game.love        the same game packed into a .love, regenerated by dev.ts
  dev.ts           bun dev server: builds, serves and answers /api/*
  zip.ts           tiny dependency-free .love packer
  dist/            the built web bundle (gitignored)
```

## Run it

```
bun install
bun run sample
```

That packs `game/`, builds the web bundle with the love.js CLI and serves it on
<http://localhost:8080>. Open it and the game immediately fires
`GET /api/random`; press **space** to fire another one (you get different data
every time), **e** to POST a body to `/api/echo`, **f** to hit `/api/fail` and
see the `onError` path, **r** to reset.

Useful flags:

```
bun run sample --compat      # compatibility engine (no pthreads)
bun run sample --port 9000
bun run sample --no-build    # serve the existing dist/ as-is
```

## The API

The dev server answers a few endpoints, same-origin with the page:

| endpoint      | what it does                                    |
| ------------- | ----------------------------------------------- |
| `/api/random` | a quote, a counter and a timestamp — new each call |
| `/api/time`   | just the server time                            |
| `/api/echo`   | echoes the request method and body              |
| `/api/fail`   | always 500, to exercise `onError`               |

Swap `dev.ts` for your own backend; the game only cares about the URL.

## Desktop

The façade in `game/lib/http.lua` falls back to LuaSocket off the web, so the
same game runs natively against the dev server:

```
LOVEJS_DEMO_API=http://localhost:8080 lovec sample/game
```

On Windows PowerShell:

```powershell
$env:LOVEJS_DEMO_API = "http://localhost:8080"; lovec sample/game
```

## The `http` module

On the web the engine preloads a Lua module named `http`
(`src/libraries/emfetch/emfetch.cpp` in the [love fork](https://github.com/dreagledr/love)):

```lua
local http = require("http")

http.request{
	url = "/api/random",
	method = "GET",                    -- GET/HEAD/POST/PUT/DELETE/PATCH
	headers = { ["Accept"] = "application/json" },
	data = nil,                        -- request body
	timeout = 10,                      -- seconds
	withCredentials = false,           -- send cookies
	onSuccess = function(res) end,     -- res = { status, statusText, body, headers }
	onError = function(err) end,       -- err = { status, statusText, body, headers, message }
}

-- once per frame, from love.update:
http.poll()

-- optional:
http.cancel(id)
```

`onSuccess` runs for 2xx, `onError` for everything else (with the real status)
and for transport failures. `game/lib/http.lua` wraps this so the demo also runs
on the desktop. See `game/main.lua` for the whole thing.

## Notes

- The release engine needs `SharedArrayBuffer`, so the server sends
  `Cross-Origin-Opener-Policy: same-origin` and
  `Cross-Origin-Embedder-Policy: require-corp`. Use `--compat` if you cannot
  send those headers (itch.io, for example).
- Web rules still apply: cross-origin requests need CORS, an HTTPS page can only
  call HTTPS, and cookies need `withCredentials = true`.
